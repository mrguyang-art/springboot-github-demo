CI/CD 自动化

通过 GitHub Actions 自动构建、测试、保存构建产物，并在版本分支上创建 Release 与发布容器镜像。

前后端独立持续集成 CI

Backend CI

backend/**

仅后端目录或 backend-ci.yml 变更时触发。

Java 21 · Maven verify · JAR Artifact

Frontend CI

frontend/**

仅前端目录或 frontend-ci.yml 变更时触发。

Node.js 20 · npm install · Vite build

Push 和 Pull Request 都配置相同的 paths 过滤。只改后端不会触发前端构建，只改前端不会触发后端构建；仅修改 docs/ 或 README 不触发这两个 CI。两个工作流支持手动运行。

静态网站发布

GitHub Pages 使用 Deploy from a branch 模式，不依赖 Pages 专用 Actions 工作流。

更新 docs/ 目录维护 HTML 页面、公共 CSS 和静态资源。
推送到 main 分支GitHub Pages 监测所选分支和 /docs 目录。
自动发布静态网站GitHub Pages 直接托管目录内容，无需额外构建步骤。
仓库设置：Settings → Pages → Source 选择 Deploy from a branch，Branch 选择 main，Folder 选择 /docs。

版本发布 CD

推送符合版本命名规则的分支（例如 v1.0.0）会触发发布工作流。

构建后端与测试在 backend/ 目录执行 Maven verify。
创建 GitHub Release附加 JAR 文件并生成 Release Notes。
构建后端 Docker 镜像以 backend/ 作为 Docker build context。
推送 GHCR发布版本号、次版本号和 latest 标签。

当前工作流文件

  • .github/workflows/backend-ci.yml — 后端路径过滤 CI
  • .github/workflows/frontend-ci.yml — 前端路径过滤 CI
  • .github/workflows/release.yml — Release 与 GHCR 镜像发布
